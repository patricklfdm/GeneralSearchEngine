# V5.2 native original inputs and whole members

This local pre-cloud stage connects the native Session to the existing complete
history controllers. It does not expose a paid Runner command or grant cloud
qualification. Immutable qualified retention, independent five-member acceptance,
protected CI partitioning and the operator workflow remain required.

## Original input preparation

`cloud_native_runner.open_native(..., prepare_workload=True)` verifies the original
protected build and package, then stages exactly five original JARs into their
existing runtime locations and constructs the source-bound Java image. Both steps
happen before lease acquisition, cost reservation or provider mutation. No Maven
build or control download is performed. The resource-only factory remains usable
by its existing admission and cleanup qualifications, but cannot execute a member.

`cloud_staging` replays the original build reports and package hashes; it does not
trust a copied success receipt. Existing destinations must contain the exact
original bytes. All existing paths are checked before the first new write.
Exclusive writes, opened directory handles, regular unlinked owned files and
source/byte rechecks prevent overwrite or silent fallback. Partial writes remain
visible; they are not repaired. Each member history rechecks the same live staging
handle. The Session closes that handle on success or failure.

Native Placement disables control downloads. Missing or changed staged controls
stop preparation instead of fetching replacement inputs. The ordinary standalone
local gates retain their existing independently hash-pinned control resolver.

## Complete original member execution

`Session.run_member` requires original factory preparation, a live native Session,
and installed Python and Java. It consumes the member once and runs its complete
frozen history list serially under the original resource claim. The existing
controllers still determine all windows, calls, business outcomes and M04 faults.
Every history is collected and independently replayed at its original and relocated
location before the next starts. Results bind original source, artifacts, three
host routes, Java installations and archive bytes. No history or business call is
resubmitted, split, or reused from a failed member.

Original results and numbered progress receipts are retained immediately, using
exclusive writes. The final execution result requires exact selected history order
and aggregate calls. Stage changes and a heartbeat at most 60 seconds apart expose
the current member, history, completed count and elapsed time. Overall time remains
soft; existing finite exchange, query, parser and authority limits remain hard.
Failures stop the sequence and retain the first execution failure separately from
any guest-close failure. The caller retains the original Session through subsequent
immutable evidence retention and cleanup.

The successful local execution receipt is `MEMBER_EXECUTED_NOT_QUALIFIED`.
Resource-only or execution-only Session exit still records a failed cloud attempt
until qualified immutable completion is implemented. No operator should invoke
this internal scope as a paid experiment yet.

## Qualification losses versus declared faults

The existing local SSH qualification deliberately loses upload, launch, update,
partition-control and terminal replies to prove original-result recovery. Native
Placement now disables these artificial losses. Its real transport still queries
original results after actual response loss, without resubmission. The frozen M04
SIGKILL, retained reopen and partition/heal are unchanged.

The restart client accepts a terminal event already received by the normal stream
or the exact next terminal event obtained from the original query. A query cannot
fill earlier missing events, duplicate an observed edge or issue another kill.
Existing local qualification keeps all its injected-loss coverage by default;
`remote_python_runtime_qualification.run(..., transport_losses=False)` separately
checks installed execution without those injections and with downloads disabled.

## Validation scope

Retained logs and the source/file index are under `target/v52-native-members`.
Synthetic orchestration tests distinguish modeled provider/JDK/history effects
from real local OpenSSH/JVM qualification. No native cloud, hosted CI, push or
workflow trigger is part of this stage. The original failed development log is
retained separately from corrected tests. Exact measured counts and scope are
recorded in `validation-summary.json`; local results are not protected CI evidence.
