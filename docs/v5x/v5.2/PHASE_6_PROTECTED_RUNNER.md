# V5.2 original Runner provenance and complete-set join

Phase 6BI connects original native closure, protected GitHub provenance and
independent provider restoration to the existing whole-member/set replay.
This is locally qualified internal implementation. No V5.2 cloud experiment or
protected acceptance has occurred, and the operator workflow is not installed yet.

## Original member closure

`cloud_execution.run_native` opens the existing native factory with complete
workload preparation, executes the selected whole member exactly once, retains
its original evidence and exits the owned context through exact-ID cleanup.
It publishes `public/member-seal.json` only after that entire sequence succeeds.
The public directory has no private SSH key, credential descriptor or raw error
text. The original diagnostics and evidence remain in their separate locations.

The Session reads back the original immutable completion and terminal ledger
while its scoped provider reader is still alive. `cloud_member_seal` correlates
those objects with the original retained manifest, thirteen resource identities,
absence checks, reservation cost, source, configuration and credential invocation.
A local close failure leaves no publishable success capability, even when the
original provider terminal record was already written. Reconciliation preserves
that record and cost; it does not manufacture a successful original Runner job.
Provisioning-only closure still records a failed workload completion.

The seal is a compact correlation record, `ORIGINAL_MEMBER_CLOSED_NOT_QUALIFIED`.
Its ledger prefix hash/count allows subsequent attempts and their costs to remain
present. An altered prefix, generation rollback, different completion or cleanup
digest fails. No copied JSON can open the native member or publish its seal.

## Exact original GitHub attempt

`cloud_runner_provenance` accepts an explicit original run ID and attempt. It
uses only fixed GitHub GETs and bounded original-artifact downloads. It does not
search for a green run or use the latest attempt as a substitute. A later rerun
does not change which original attempt is being inspected.

The collector requires:

- Exact repository/owner IDs, source, master branch, manual event and
  `.github/workflows/v52-replication-evidence.yml`.
- One successful `V5.2 replication runner` job on the selected attempt, with
  successful ordered identity, authentication, execution and upload steps.
- The actual workflow bytes from the clean source checkout, independently
  matched to the original GitHub Git blob. Its single `runner` job must use
  `v52-cloud-benchmark`, master-only admission and unconditional required steps.
- Exactly one `v52-runner-<run>-<attempt>` artifact, its original upload interval,
  digest, size, repository/source identity, expiry and stable metadata.
- A bounded ZIP containing only `member-seal.json`, with no duplicate, link,
  traversal, encryption or additional diagnostic/private file.
- The seal's credential context and execution times inside the original job's
  execution step. Run, job, artifact inventory and master are observed again.

Pagination is complete and bounded; truncated/ambiguous inventories reject.
Original completed experiments have no artificial recency limit. Current
collection observations are limited to 900 seconds and artifact availability is
still required. Current admission/cleanup freshness rules remain separate.

The native factory reads the actual protected workflow from disk. It currently
fails closed because that workflow has not been added; the test workflow is a
synthetic fixture, not a deployed entry or a future workflow represented as fact.

## Complete-set acceptance boundary

`cloud_acceptance.verify_native` owns both collectors and the original replay:

1. Select all five distinct original requests and distinct run/attempt pairs.
2. Restore their immutable evidence/completion/cleanup objects from the original
   ledger with the fixed native provider reader.
3. Collect each original GitHub seal and compare it to those independently
   restored objects and the preserved ledger prefix.
4. Replay every original whole member. Its independently reconstructed runtime
   invocation must equal the protected invocation, including all fifteen M01
   histories. Missing/changed originals stop; no workload is retried.
5. Require the unchanged five-member aggregate: 33 histories, 27,428 reads,
   2,760 updates, 2,700 M01 offered seconds and 439 formal evidence negatives.
6. Recheck source/configuration/workflow before emitting a qualified receipt.

Only this native join can emit `gse-v52-protected-cloud-set-v1` PASS with
`fullRemoteQualification=true`. The object reader, seal, GitHub collector and
standalone byte replays retain their NOT_QUALIFIED results. Verification itself
creates no VM or workload; its `paidCloud=false` describes that operation, not a
claim that the original experiments were free. Selected reservation costs and
the full ledger's accumulated reservation costs are reported separately.

The original member and complete-set join print progress at least every minute.
No aggregate stage timeout or cost hard stop was added. Existing request,
parser/storage, credential freshness, lease and operation-grace bounds remain.
