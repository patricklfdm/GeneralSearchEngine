For each bulk operation, 240 requests represent 3840 document operations. The
reported bulk latency is per atomic request. Index operations do not imply a
document count. Every healthy operation completed successfully; measured rejected,
timed-out and indeterminate counts are zero. The full JSON retains all four
windows separately, sample counts, document counts and scheduler delays.

Replicated mutation medians are approximately 4–6 times the paired single-node
control. Entry/proof quorum communication, forces and ordered publication are
additional work; these measurements do not isolate their individual causal costs.
Read results remain semantically equal. QUERY latency is of comparable scale;
faster GET observations on this small workload are not a general speedup claim.
There is no V5 latency-ratio pass threshold, and V4's old thresholds do not apply.

`0.999452`, C3 `1.002791`; control ratios are `0.985655`, `0.989391`, `0.980361`.
These paired windows show variation as well as instrumentation cost; a ratio below
one does not mean instrumentation has a negative cost.

## Reproduce review and registration

From this repository, with the five downloaded roots, regenerate to a fresh local
file. This command performs full independent member/set validation, then derives
statistics from reassembled raw chunks. It does not trust the convenience
`runtime/` copy or a supplied validation summary.

```bash
evidence_roots=(
  target/v50-run-review-35394514093/artifact/evidence
  target/v50-run-review-35402218541/artifact/evidence
  target/v50-run-review-35407548985/artifact/evidence
  target/v50-run-review-35414044623/artifact/evidence
  target/v50-run-review-35415871650/artifact/evidence
)
python3 -m scripts.v50.cloud_baseline review "${evidence_roots[@]}" \
  --output target/v50-phase6-review-reproduced.json
cmp docs/v5x/v5.0/phase6-cloud-review.json target/v50-phase6-review-reproduced.json
python3 -m scripts.v50.cloud_baseline register "${evidence_roots[@]}" \
  --review docs/v5x/v5.0/phase6-cloud-review.json \
  --registry target/v50-phase6-registry-reproduced.json
cmp docs/v5x/v5.0/cloud-benchmark-baselines.json target/v50-phase6-registry-reproduced.json
python3 -m scripts.v50.cloud_baseline check \
  --review docs/v5x/v5.0/phase6-cloud-review.json \
  --registry docs/v5x/v5.0/cloud-benchmark-baselines.json
```

The `check` command checks the compact registry/review binding only. Actual
registration always reruns validation from all five raw bundles and requires an
exact regenerated-review match. It refuses a second registration, renamed entry,
incomplete set or changed measurements. The tracked registry does not itself mean
protected review has merged; the [checklist](PHASE_6_CHECKLIST.md) records that gate.
