## Delivered boundary

The internal node now fences recovery with a higher durable promise quorum, preserves
valid committed proof prefixes, reconciles uncommitted or incomplete entry tails,
and restores application state before committing the activation NO_OP. Followers
catch up through bounded batches or immutable snapshot transfer. Replacement disks
remain non-voting until reconstruction; the configured leader's erased disk requires
both surviving followers. Atomic generation publication and a two-source recovery
floor permit restartable physical compaction.

See [the recovery design](PHASE_4_RECOVERY.md) for record IDs, installation order,
limits and failure behavior. The original seven-file fixture and public API inventory
remain unchanged. The new optional generation records and replacement NODE extension
are candidate-format additions, with independent Python/Java golden-byte inspection.

```bash
MAVEN_ARGS=-Dgpg.skip=true scripts/verify-reproducible-build.sh
./mvnw -f reactor/pom.xml clean -Prelease -Dgpg.skip=true verify
scripts/verify-v50-phase1-foundation.sh --skip-build
scripts/verify-v50-phase2-storage.sh --skip-build

scripts/verify-consumer-projects.sh
./mvnw -Partifact-compat -DskipTests verify

```

Java network tests and Phase 3/4 process gates require loopback TCP permission. Run
reproducibility before collecting `target` evidence because clean removes generated
workspaces. Maven can run offline with complete caches. The Phase 4 gate resolves
published V4.4 into `target/v50-control` by default; `GSE_V50_CONTROL_JAR` may identify
an existing file, whose checksum and loaded code source are still verified.

The gate retains source SHA and dirty-tree status, PIDs/lifetimes, controls/events,
SIGKILL barriers, exit records, copied storage, hash inventories, independent reports,
corruption rejections and published-control output. CI uploads `target/v50-recovery`
even after failure. These working-tree results are candidate evidence; protected PR
and exact-master CI must produce their own exact-source acceptance.

## Remaining gates and limits

Public engine/bootstrap entry points remain reserved until complete offline group
bootstrap and lifecycle admission. Catch-up is explicit internal maintenance; there
is no background scheduler. Strictly corrupt promise/proof/committed history rejects
and needs an explicit replacement workflow. This is not generic corrupt-store repair.

Snapshot ancestry, transfer size and private rebuild memory remain bounded as documented;
no performance or indefinite-retention claim is made. SIGKILL is process-failure
evidence, not kernel/device power-loss certification. No paid cloud, election,
membership change, signed release or published V5 artifact is included.

Protected Phase 4 review and exact-master CI precede Phase 5 hardening. The bootstrap/
lifecycle gap must remain visible and be completed against the frozen authority/API
contract before public engine admission is enabled.
