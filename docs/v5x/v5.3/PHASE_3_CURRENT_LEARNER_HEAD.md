# Phase 3 — current typed learner acquisition head

The [A22 contract](PHASE_3_CONTRACT_AMENDMENTS.md#a22--live-current-typed-head-for-subsequent-acquisition)
connects the reclaimed current source to the next learner acquisition. It requires
actual semantic reopen of the retained current backup, complete forced predecessor
retirement and the same live parent. A sealed internal capability prevents plain
source/receipt values from substituting for that owner.

The native client retains its original deadline, same resource pool and one
LEARNER receiving slot. It verifies the new source against the current head's
terminal ancestor. Close, mutation and path overlap revoke or refuse the operation;
cleanup releases receiving resources without releasing the current generation.
The first-successor installer explicitly refuses this capability, protecting its
immutable old plan. The next installation belongs to a bounded reusable-slot owner.

Focused results and exact source scope are recorded in
[the receipt](phase3-evidence/current-learner-head.json). A conditional-history TCP
test is distinct from native consensus history. The independent three-revision
`V53CurrentHeadNetworkTest` is prepared for the final hosted queue; compile alone
does not establish its execution or independent physical replay.

The [rolling lifecycle design](PHASE_3_LEARNER_ROLLING_PLAN.md) records the next
implementation boundary. Repeated installation, cancellation, matching INTENT,
native/process-death qualification and full Phase 3 remain OPEN.

## Retained focused results

The corrected immutable build passes all nine methods with no failures, errors or
skips in 189.2 seconds: two current-head methods, five preparation methods and
two resource-owner methods. Both actual loopback TCP and original typed filesystem
owners are exercised, while the history's voter forces remain conditional.

The TCP case acquires complete original bytes after retirement and parent/typed
reopen, keeps one current GENERATION plus one receiving LEARNER, refuses initial
admission/installation reuse, and cleans only receiving resources. Closing the
typed owner during a real reply revokes acquisition while preserving the current
source and backup. The other case rejects unpromoted/unretired handles, every
reserved scratch-path overlap and an exhausted original deadline, and verifies
parent-close revocation without leaked reservations.

The first build remains retained with one failed TCP method: its test service
accepted only transfer messages and omitted STATUS discovery, causing EOF after
ROOT retrieval. The corrected test uses the actual journal's discovery responder
and records handler errors. All production inputs are identical between the two
builds; the failure is not labeled a production timing or retry fix. The seven
older component methods and the path/lifetime method already passed in that build.

The corrected build also compiles `V53CurrentHeadNetworkTest`, containing the whole
native PREPARE 1/2/3, retirement and cold-reopen history. It has **not run** here;
independent native replay and process-death qualification remain pending. These
component results neither install a third revision nor close Phase 3.
