# Phase 3 — installed original learner successor

The [A18 contract](PHASE_3_CONTRACT_AMENDMENTS.md#a18--installed-original-learner-successor)
connects [prepared-source refresh](PHASE_3_LEARNER_PREPARED.md) to durable local
installation. A complete received generation is retained using its existing file
and resource owners from the parent's exact resource pool, under an original immutable plan and an exclusive sidecar
lock. Its selector is forced only after the original source has been retained,
its ancestry verified and both move parents forced.

A returned view exposes the newly selected certified capsule. It does not issue
a new remote durable-copy observation, reuse the source voter's PROMISE as the
learner's vote, open the live core, or claim a revision-2 typed readiness receipt.
The previous typed owner remains required while accessing this view. Its close
revokes view access while the parent still accounts for all original disk bytes.

Parent reopen reads the original install decision, reserves the retained source
and images, and refuses changed source bytes/inodes, unknown files or incomplete
plans. Complete candidate plans and exact partial selectors can be resumed. Reopen
repeats the predecessor semantic preparation before exposing the selected successor.
No caller-supplied replacement plan repairs missing original evidence.

The original source and successor occupy the two existing generation slots. The
maximum private metadata sum is 1,988 KiB under the unchanged 2 MiB MISC lease.
The original remains intact until explicit retirement is implemented. This batch
therefore allows one installed successor and refuses a second installation; it
does not claim unbounded revision refresh or completion of the learner lifecycle.
