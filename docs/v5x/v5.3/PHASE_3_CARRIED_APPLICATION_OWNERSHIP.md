# Phase 3 — carried application export, FLOOR and ledger ownership

Phase 3 remains **OPEN**. This batch extends the retained INTENT/halt and
FINAL/SIGKILL application-ACK histories through temporal export authority,
complete-copy FLOOR acquisition, and continuous peer/future retention revisions.
It requires the original process, independent physical and
[callback/TCP replay](PHASE_3_CARRIED_APPLICATION_PROTOCOL.md) first. No new native
producer, runtime change, resource increase or hosted/cloud run is involved.

## Interrupted export authority

The leader's local certificate and each selected voter's PROOF become available
only after their original completion callbacks. A PROOF observation is bound to
that original record, permanent storage identity, ballot and view. Its alias
uses the vote-observation wrapper; hashing the receipt alone is insufficient.
Receipt capability ends at the next promise or original process death. A local
application ACK that has not reached publication supplies no export capability.

The ordinary export reader still validates complete reconstructed transfers,
current generation windows, selected journal records and frozen sources. The
old application-retirement projection validates the exact retirement before
excluding its storage callbacks from the fresh slot. It preserves interleaved
socket observations and original event indices. Both exporter and receiver must
remain in one original lifetime through commit delivery.

Recovery can retire multiple old frozen sources between two parent snapshots.
The previous one-transaction assumption cannot describe these originals. The new
adapter derives distinct retirement ends in the runtime's sorted source order,
requires one complete transaction per source and checks the deletion count
against that source's original members. The mandatory force reader independently
derives the underlying transaction authority and journal compaction. One early
retirement boundary cannot terminate all retained sources, and a later source's
boundary cannot extend an already-retired source's capability.

## Complete-copy FLOOR ownership

Expected owners and copy sets are derived from original snapshots before reading
FLOOR callbacks. A staged owner is deferred during a campaign. After its exact
old-end retirement and new ACCEPT, it participates in slot maintenance. The
interrupted application lifetime has completed remote PROOF, so all selected
voters' maintenance is required.

Every acquired remote copy still needs its correlated discovery, complete packet
and metadata transfers, actual matching local image bytes, and local generation
recheck before FLOOR creation. Startup STATUS hints cannot substitute for a
complete retained copy. The three-copy/three-source local pin is derived from
original capacity demand and changes only local physical copying; all logical
governing witnesses, remote acquisitions, force order and release remain checked.

## Continuous retention revisions

Peer and future ledgers start at the independently reconstructed admitted prefix.
Cold-open snapshots compare to the current derived revision; they never seed or
reset it. The application adapter admits original CERTIFICATE recovery after the
same exact peer/future reseals required by the old reader. Fresh slot projection
preserves indices and prevents old replay callbacks from being counted twice.

Every ledger write has an original owner lifetime, predecessor, revision and
cause. Selected-install completion, captured sources, maintenance observations,
publication, future recording, ACK, promotion and clearing are checked in order.
A write cannot straddle group death or borrow an earlier lifetime's force.

## Remaining work

These are component qualifications. The originals contain no complete transient
capture or continuous whole-runtime resource sidecar. Export capabilities and
complete-copy lifetimes do not by themselves prove every export allocation,
release or simultaneous resource maximum. Full transient/resource composition,
remaining native crash axes, DATA/internal-core interruptions and final-source
hosted qualification remain required. Historical ACCEPT/PROOF readers keep their
old default restrictions; this adapter does not silently broaden those receipts.
