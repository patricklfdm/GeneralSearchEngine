## Durable ownership across elections

Native owners with initialized peer and future journals retain every selected
source's original GSFT as a separately indexed object. They install the receiver's
GSRS intent and those originals before returning installation success. Owners
without the complete native journals still refuse unresolved future references.
An unresolved result never becomes a published endpoint merely because it was
selected or copied.

A later original PROMISE/BASIS captures a flat descriptor of the still-pending
proofs. The descriptor names the capturing owner separately from each original
proof owner. Each original byte sequence remains bound to its original owner,
parent, logical entry, target and intended peers. The new source must own the
actual carried ACCEPT for that same parent/entry; a different ballot is allowed,
but a different logical result is not. Missing originals, altered bytes, foreign
owners or conflicting results refuse. Copied proofs create no new voting ACKs.

Old derived application work may retire only through the existing typed replay
and durable retirement marker. When a newer selected prefix already covers the
target, its exact local original BASIS must retain the pending proof before
derived files may disappear. The original vote and frozen source remain. The
covering-source equality check reconstructs its original retention snapshot,
never a later mutable ledger. The installed prefix authenticates every required
parent and target before ordinary endpoint promotion and local proof clearing.

For an unpublished carried target, actual reacceptance transfers the logical
entry to the newer ballot. Inactive-generation retirement recognizes this checked,
already-forced successor through the existing `MembershipContextTail.successor`
predicate. It still requires a real governing floor, exact entry/payload bytes and
all original ancestry. An arbitrary copied higher ACCEPT cannot authorize deletion.

## Publication and recovery

Publication embeds a receiver-local completion descriptor with the exact original
selected intent and pre-publication ledger. The actual certified prefix must cover
all inherited targets. After the selector switches, the native owner promotes
their possible peer endpoints before clearing its local temporary future proof.
Reopening performs the same completion before exposing the owner.

The descriptor fixes an exact local revision/digest successor. An exact completed
revision is checked; later native revisions are not rolled back, because actual
complete-copy observations may have narrowed uncertainty. Original lower endpoints
cannot be discarded by a claimed newer cut or by publication alone. The new
materialization retains the descriptor and required original objects while this
completion can be interrupted.

## Private format and resource boundaries

These are private auxiliaries in the unpublished 1.3 source packet, not new
catalog record kinds, peer ACKs or standalone permission to vote:

| Object | Encoding and bound |
| --- | --- |
| GSFS | 48-byte checksum header; canonical root/capturing-owner plus sorted original-owner/SHA-256 references; at most six distinct proofs; 32 KiB total |
| GSRP flag 2 | Existing wrapper and original PROMISE/ledger, with one 32-byte GSFS reference; flags 0/1 keep their previous encoding and maximum |
| GSFC | 48-byte checksum header; selected-intent digest, 4-byte length and exact pre-publication ledger; at most `48 + 32 + 4 + 65536` bytes |

GSRS retains the source envelopes and descriptors; originals remain separate
indexed objects. Each GSFT is still at most 3 MiB. Complete packet/generation
admission still enforces the existing 32 MiB ceilings and per-object limits.
No extra application image or enlarged resource ceiling is introduced.

Before SELECTED, an imported unresolved target reserves the ordinary ledger's
64 KiB completion candidate within the shared journal allowance. A local future
already reserves that same slot, so the reservation is shared rather than counted
twice. Already-covered targets reserve their exact selected merge. A one-byte-short
admission must fail without changing original file bytes. These bounded examples
do not establish maximal lifetime or arbitrary repeated-campaign progress.

## Qualification and remaining work

The continuation fixture begins with real public stable-three EMPTY bootstrap,
original votes and applied ends. Nodes 1 and 2 own different future intentions;
node 3, which owns neither, supplies the longest selected prefix. After installation,
node 1 remains offline. Nodes 2/3 perform another original campaign, reaccept,
maintain a governing floor, certify, publish, observe actual copies, reclaim and
start the following campaign. Exact original proof identities must survive.

The independent `scripts.v53.inherited_future_evidence` reader derives bootstrap,
all original votes, GSFS/GSRP/GSRS/GSFC, generation files, ledger revisions and
application results before comparison. Fresh source UUIDs are the only observed
grant inputs. Optional publication-process evidence additionally requires the
complete halt/SIGKILL matrix and exact interrupted/recovered file inventories.
Original evidence must pass before any negative mutation can count as rejected.
Process deaths are not power-loss evidence.

The [source-bound receipt](phase3-evidence/inherited-future.json) binds the native
history, 18 halt/SIGKILL cases, 36 fresh JVMs and nine live ownership probes.
Original-first normal replay and optimized replay after archive relocation agree,
including all 16 exact negative rejections. All 661 Python tests pass normally
and with assertions disabled. Four continuation tests cover a second election
without the original holder, covered-target installation, exact admission versus
one byte short, and five cleanup/installation exception boundaries with reopening.
Those five covered exceptions are Java-only checks, not additional SIGKILL or
independent covered-history evidence.

The process matrix passed in a build whose aggregate failed the separate covered
recovery test: after forcing a pending selector, the test incorrectly attempted
another cleanup transaction. Its corrected caller resumes installation once the
derived staging is gone. All four continuation tests then pass on identical
production Java; neither the original failed aggregate nor earlier production,
test preparation or worker failures is relabelled as success. The receipt keeps
the affected old regressions separately from the new qualification.

Some earlier temporary build directories became unavailable; retained logs,
source inventories and existing archives are distinguished from the newly
retained isolated builds. No missing raw tree or report is reconstructed.

Required next work still includes complete source/completion headroom over repeated
