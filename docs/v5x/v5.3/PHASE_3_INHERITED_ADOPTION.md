# Phase 3B — inherited future obligations across certified removal

This native qualification extends [inherited continuation](PHASE_3_INHERITED_FUTURE.md)
through a real configuration change. It does not enable public membership or
complete Phase 3. The implementation uses the existing production storage and
proof checks; this batch changes test orchestration and independent readers.

## Original history and authority

Four publicly bootstrapped voters install an actual selected round. Three voters
ACCEPT, PROOF, certify and apply BARRIER 1 without publishing it. Two different
owners durably retain future dispatch obligations to nodes 2 and 3. A new election
installs both original proofs on node 4 even though that node never accepted the
entry and has neither a local pending vote nor a local future transaction.

The three other voters retire only their superseded derived application work,
carry the exact original entry, and publish it under the fresh round. They then
complete RESERVE, PREPARE, READY, SEAL, old-majority INTENT and joint-majority FINAL
for an actual four-to-three REMOVE. Native ledger reconciliation occurs explicitly
at the configuration boundaries; it is not an autonomous scheduler.

The removed node adopts that certified new prefix using the complete original
retained ancestry. Adoption promotes both inherited obligations into its ordinary
ledger before exposing completion. Nodes 2 and 3 retain possible endpoints 0 and
1; there is no invented observation that either remote node completed delivery.
Duplicate adoption and native reopen preserve the exact files. A new grant on the
removed node is refused. The survivors then install a fresh new-view campaign,
publish BARRIER 8 and RETIRE 9, and complete the existing floor/reclamation path.

Omitting the original ancestry is separately rejected before changing authority
or any retained file. Historical proof bytes are verified and reused; hashes in
old certificates are not converted into new remote voting observations.

## Required ancestry in the test driver

The shared cross-view driver previously started its ordinary histories at genesis
with no peer ledger. This history also needs an interior original selected parent
and peer endpoint at cut 1. The corrected driver obtains the proofs from the

## Qualification boundary

The final Java snapshot completes the reference history and fourteen halt/SIGKILL
cases at seven actual adoption/ledger boundaries: the adoption fence, selector
force, selector rename, retention prefix write, retention rename, inherited
promotion and pre-return. These use 28 fresh JVMs and seven live lock probes.
Missing-ancestry refusal, duplicate adoption and reopen are also checked.

Independent Python replay derives bootstrap, original grants and all nine slots,
including exact certificates, application ends, source objects, selectors,
ancestry order and ledger revisions. It verifies the original first, then every
interrupted/recovered file inventory and force/death/lock result. Fourteen history
mutations and seven process mutations must reach their exact expected rejection.
Normal and relocated optimized replay agree, including all 21 exact negative
rejections. The final package passes all four requested suites. Existing cross-view
replay additionally passes four profiles, 60 slots and 16 evidence negatives;
the existing native adoption reader passes 38 process cases and six negatives.
The campaign-ancestry regression has Java evidence only. The
[source-bound receipt](phase3-evidence/inherited-adoption.json) retains the exact
source/build inventories, terminal logs, reports and archived raw attempts.

The first four histories failed because the test driver omitted required original
ancestry at INTENT, FINAL, the next campaign or BARRIER. Production rejected these
omissions; the failed evidence remains intact. The fifth passed but predates the
explicit missing-ancestry negative. The independent reader's initial RETIRE
comparison sorted fresh and old proof groups together; the corrected model
preserves their derived write order without rewriting original Java evidence.
