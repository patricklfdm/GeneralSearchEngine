# Admitted campaign fixture ancestry

The maximum-image producer exposed a test-driver omission after its second
BARRIER: the next campaign retained the prior frozen source at index 1, which
had become hidden inside the stable RANGE ending at index 2. The driver passed
no ancestry proof. Production correctly refused installation with
`missing retained installation ancestry`.

The small-image regression reproduces the identical sequence on five actual
publicly provisioned owners: campaign, BARRIER, campaign, BARRIER, campaign.
It fails against the original driver and passes when the driver supplies the
already forced applied-end bridge for that exact old source. Direct capsule
anchors still receive no extra proof; selection inputs and production code are
unchanged. The fixture also exposes its existing request constructor and an
optional observation hook for the separate maximal-image qualification.

The independent reader derives the old source cut and its bridge from the
previously verified snapshots. It checks all physical states, exact calls,
force-before-return order, unchanged application state and owned observations.
Four original-first mutations remove/change ancestry, change the selector or
remove the selector force; all must fail for their intended reason. Normal and
optimized replay must agree. The existing four-profile REMOVE evidence must
still pass all 16 mutations and its portable replay.

Retained results and source/build bindings are in
[the local evidence index](phase2-evidence/admitted-campaign-ancestry.json).
This small regression does not turn the earlier failed maximal-image attempt
into a successful execution. That attempt remains archived with its original
source map, snapshots and failure. Maximal bytes, process death and the overall
Phase 2 closure remain separate obligations.
