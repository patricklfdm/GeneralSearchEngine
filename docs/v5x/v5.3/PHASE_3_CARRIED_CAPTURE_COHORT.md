## Admission

The local execution/cohort and hosted receipt schemas advance to v2. A v1
two-member success cannot satisfy the larger catalogue. The dynamic workflow
matrix uses the new four cases while retaining maximum parallelism two, pinned
tools/actions, offline dependencies, no native retries, once-per-minute progress,
90-day failure retention and separate downloaded verifiers. Ordinary Required
CI, cloud and release workflows are unchanged.

The same frozen source/build/toolchain/reader seed supplies each original.
Admission requires the exact single JUnit method and command, successful native
and immutable-source collection processes, no rerun or skipped test, unchanged
source/classes and exact raw inventory. Collection alone remains `PARTIAL`.
New process wrappers contain every capture internally; they cannot borrow an
external sidecar. Existing ordinary sidecars remain mandatory.

The new [composition reader](../../../scripts/v53/native_carried_capture_history.py)
first validates the entire original chain: process boundary, storage snapshots,
callbacks, TCP replies, temporal exports, complete-copy FLOOR lifetimes, retention
revisions, resources, all seven captured families and physical owner charges.
An invalid original stops before any mutation. Then each family's existing
qualifier must return the same original as its prerequisite, preserve the input
inventory and reject its complete exact vector:

These are capture/owner negative suites after the full positive prerequisite;
they do not claim execution of every lower-level reader's negative suite.
Owner mutations retain the accounting totals but substitute an unrelated owner
for a physically required charge. Original-first checks, exact reasons, case
identity, family counts, original process identities and all scope flags are
checked again before aggregate admission. Shortened or foreign receipts fail.

Full original ownership replay can exceed the existing 8 MiB JSON receipt
limit. After that replay, the verifier stores a compact owner summary: the
complete coverage hash, eight per-owner and snapshot hashes, exact callback
counts and ten original mutation targets. Every raw file and resource trace
remains in the original archive and is replayed on download. Summary generation
changes no original and raises no read limit; a test exercises an oversized
mapping and validates the result through the existing bounded reader.

The whole subset therefore requires four distinct originals and **1,022 exact
negative results**. The broader source catalogue remains twelve subsets, now
**554 histories, 248 execution groups, 488 raw archives and 520 selected jobs**.
The qualification plan and complete negative-selector hash change together;
twenty existing requirement witnesses remain intact. Counts describe planned
work, not successful execution or coverage inferred from totals.
