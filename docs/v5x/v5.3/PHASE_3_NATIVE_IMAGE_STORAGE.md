# Native maximum images at one original callback

The [maximum native required-four entry](PHASE_3_MAXIMUM_NATIVE_ENTRY.md) now
requires seven actual calibrated images at one owner's one original callback.
A maximum-sized seed followed by a successful history is insufficient without
this simultaneous observation. This uses existing source-retirement captures
inside the uninterrupted required-four history; no new producer, scheduling
group or split history is introduced.

## Original-first derivation

The complete physical, authority, resource, custody and close replay and its
150 exact negatives run first. `native_retirement_storage` then reads every
original source-retirement transaction and binds its actual callback and capture
events to the same node's resource journal. Full journal replay includes all
intermediate transitions and clean closure. A storage release/reacquire during
capture rejects even when the endpoint totals match. CONTROL/WAITER changes may
occur independently while the writer holds the original storage.

Every captured replica file maps to its exclusive live lease. Joining and
learner retention records share `JOURNAL / membership-grants`; an adopted
certificate belongs to its generation or floor-copy SOURCE. Both the active and
candidate journal files count toward that same reservation. Unknown paths,
missing owners, pending claims and undersized leases reject. Floor image ordinal
owners come from complete original transactions, not a partial surviving list.
Segmented captures supply validated identities without materializing all images.

Acceptance requires one captured state containing seven distinct image paths
and seven distinct APPLICATION owners, each with exactly **67,108,832 bytes**
and the bootstrapped image hash independently derived from the original plan.
Equal contents still count as separate file copies. The simultaneous total is
**469,761,824 bytes**, or seven calibrated images; it is not seven rounded 64 MiB
reservations. Copies from different nodes or callbacks cannot be added together.

The receipt retains the first matching callback, original event/capture/resource
sequences and hashes, image paths/owners, physical metadata/application/staging
bytes, observed charges and protected completion headroom. All checked callback
summaries are covered by a digest. The v2 maximum-native wrapper requires this
projection and rechecks the seed and whole-original inventory afterward. The
collector, independent hosted verifier and final cohort inherit the mandatory
check; an old v1 receipt cannot be relabelled as current qualification.

## Scope and remaining execution

This is a same-callback image/file/lease observation. It does not establish that
the conservative metadata envelope, queue maximum and seven images occur
simultaneously. Physical file lengths, resource reservations, disk blocks and
process memory remain different quantities. No independent maxima are summed.
The result keeps combined-resource, whole-reader-memory, final-source and
Phase 3 qualification false.

Production Java, resource/time limits, the twelve history subsets, five
supplemental originals, two maximum components and 150-negative native vector
are unchanged. No workflow is dispatched. Full maximum execution and native
Linux environment setup remain deferred as requested by the operator.

The [development index](phase3-evidence/native-image-storage-development.json)
distinguishes synthetic validator tests from replay of a retained small-image
history. The latter can establish the projection against an actual original;
it cannot qualify a maximum run or the final-source cohort. Historical originals
remain immutable. All five Phase 3 closure gaps remain open.

## Development result

The retained required-four original produced at `78403d87` passes the current
complete positive physical/resource replay followed by the new projection in
458.6 seconds. All 330 captured states have exact file/lease coverage; 70 contain
seven images at one callback. The first such point has seven 837-byte images
(5,859 application bytes), 366,780 metadata bytes and 372,639 total file bytes.
Its 35,981,764-byte metadata reservation and 245,505-byte queue are separate
observations, not physical file extents. The before/after original inventory
remains identical. The maximum-image requirement correctly rejects this small
original. This replay does not rerun the unchanged 147 historical negative cases
or the future maximum-native 150-case vector.

There are 161 passing related Python tests and 19 contract tests. The 51
optimized-Python checks and 26 final headroom checks overlap those suites.
Regressions cover reservation-only counts, split callbacks, wrong image size or
content, foreign leases, intermediate release/reacquire, missing closure,
segmented inventory without image materialization, old receipts and a failed
original before projection. Synthetic maximum extents test validator arithmetic;
they do not represent a large runtime execution.
