## Complete histories and stages

1. `prepare` freezes one clean source, reference class inventory, actual portable
   tools and an isolated offline dependency repository. It reuses the pinned
   process setup and preparation build; it does not execute the seven histories.
2. Seven `execute` jobs each run one complete native history once. The four
   `slot-*` histories retain old BARRIER ACCEPT/PROOF/CERTIFICATE/APPLIED through
   carried completion and the fresh barrier. The three `round-*` histories keep
   stable activation/BARRIER/DATA, discovered stable startup, or carried APPLIED
   completion and readiness together. No lifetime, carried/fresh pair or owner
   is split. Failed originals are retained and never reused as successful input.
3. Seven independent `verify` jobs download the exact seed and raw artifact for
   their source/run/attempt. They admit original source, tools, class bytes,
   process/JUnit receipts and inventories before physical/lifecycle replay and
   the full applicable negative vector. Producer assertions alone cannot pass.
4. `aggregate` requires successful execute/verify stages, exactly seven verifier
   artifacts, seven distinct original plans and producer/raw archive hashes, and
   all **287** exact negative results. A missing, failed, cancelled, duplicated,
   relocated-without-provenance or mixed-attempt input rejects. Its component
   PASS does not qualify process death, arbitrary carried payloads, all profiles,
   complete automatic competition, combined peak resources or Phase 3 closure.

Execution and replay each have `max-parallel: 4` and `fail-fast: false`. This
bounds simultaneous independent jobs without shortening a history or changing
its original request/round budgets. A heartbeat is emitted each minute. All
success/failure artifacts retain 90 days and bind the full source/run/attempt.
Summaries show case, exact source, run/attempt, counts and identity hashes. The
hosted platform job limit remains 360 minutes.

## Invocation and scope

Only explicit `workflow_dispatch` or a push to
`experiment/v53-round-histories` enters this workflow. Ordinary feature pushes
and PRs do not enter it. Permissions are `contents: read`; there is no cloud
identity, paid experiment, release authority or Required-gate change. Existing
pinned action SHAs, Java 21, Python 3.11 and Maven 3.9.11 are reused. Checkout,
workflow source and artifact contexts must agree.

All stages of a complete accepted cohort belong to one run attempt. A partial
rerun cannot borrow a seed or verifier result from an earlier attempt. Preserve
all failed originals; later success does not change their recorded outcome.
This implementation does not itself authorize push or dispatch.

The current planning inventory is eight hosted subsets and **456 planned whole
histories**, adding seven to the previous 449. These are planned component
histories, not a completed execution count, covered S rows or a completion
percentage. The carried fixtures use BARRIER payloads; carried DATA/control/
INTENT/FINAL and native process cuts remain separate outstanding axes.
