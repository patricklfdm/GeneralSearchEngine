# Phase 3 — original learner predecessor retirement

The [A21 contract](PHASE_3_CONTRACT_AMENDMENTS.md#a21--original-predecessor-retirement-after-forced-handoff)
adds physical retirement after the original ownership handoff. A single bounded
decision binds the active head and original source-retention inventory. It must
be forced before deleting any covered file. Both old typed handles remain revoked.

The recovery path validates the current retained source independently before
resuming removal. Only a complete original retirement decision permits missing
covered predecessor members. Unknown files, replaced inodes, altered bytes,
partial decisions and missing current originals are preserved and refused.
Original ROOT/NODE/admission files are required complete, without recovery repair.

Old source and typed-backup leases are released only after exact removal and
directory forces. The current source and current typed backup stay retained and
accounted. An initial admission anchor constrains current ancestry; it does not
replace a source capability or materialize an application. A typed current receipt
still requires the actual core decoder on reopen.

Focused results are tracked in [the component receipt](phase3-evidence/learner-retirement.json).
These conditional histories and synchronous exceptions do not establish native
multi-revision or process-death correctness. Those cases stay in the
[deferred acceptance queue](PHASE_3_DEFERRED_ACCEPTANCE.md). Alternating bounded
refresh, cancellation cleanup, matching INTENT and full Phase 3 remain OPEN.

## Retained focused results

The immutable local build passes all 16 methods with zero failures, errors or
skips in 814.8 seconds: six new retirement methods, three existing handoff
methods, five preparation methods and two resource-owner methods. The six new
methods contain 13 independently constructed conditional three-voter ADD histories.
They exercise actual core image decoding and original filesystem ownership, not
a native election or distributed revision campaign.

The tested histories cover complete removal and typed cold reopen; preserved
partial retirement records; complete decisions interrupted before force, after a
member deletion and after final parent forces; unknown/replaced remaining members;
changed current source; missing retirement decision; and current-source mutation
at the deletion boundary. Reservations remain held before final removal forces.
After successful retirement this fixture retains one GENERATION and two
APPLICATION leases, with no old LEARNER lease. Current source/backup bytes remain
unchanged. Repeated retirement and cold reopen preserve the result.

All 486 production source/resource/POM inputs match the final workspace. Runtime
inputs, compiled-class hashes, Surefire results, commands and thread samples are
retained in the receipt's archive. Sampling observed CPU-active ownership checks
advancing between test methods; it is diagnostic evidence, not a timing benchmark
or proof that all delay causes are fixed. Final hosted qualification can schedule
independent methods/history groups in parallel, preserving each complete original
history. No hosted workflow or paid cloud experiment was started here.
