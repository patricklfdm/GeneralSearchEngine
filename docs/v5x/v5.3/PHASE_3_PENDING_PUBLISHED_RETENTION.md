# Pending-linked published INTENT retention

Phase 3 remains **OPEN**. A completed pending-owned progress download can now
force its full INTENT source while retaining the original pending history and
ACK. `retainPublishedIntent` requires a private capability from that live
acquisition. A decoded source, unrelated pending owner or ordinary INTENT API
cannot enter this route.

## Original relationship and transaction

The original pending owner stays attached to the same typed learner and resource
pool. The private INTENT plan records its directory/inode, plan hash/inode,
retained source inode, typed receipt, marker hash/inode and ACK hash/inode.
Both original histories and the exact INTENT entry/checkpoint are checked before
the force transaction. A separately valid later certificate for the same value
remains acceptable. The live parent relationship is checked around writes and
before the result is returned.

The actual receiver detaches its existing owners before creating the decision.
The complete plan is forced before the source move; all source members and the
source/transaction/move-parent directories are forced before success. Failure
preserves both histories, including staged source bytes when the plan is torn.
The pending history remains SOURCE, the full source remains LEARNER, and the
second GENERATION category stays available. Images remain separately charged.
Closing a download after transfer cannot remove the retained full source.

## Explicit boundary

This component returns a forced JOINT or COMPLETED result. It intentionally
cannot issue the private voter-install capability until linked cold recovery
and complete custody preserve both sides. Ordinary INTENT/pending resume still
rejects coexistence before writes; it cannot silently discard the pending ACK
or reopen a second receiving slot. No new public ready state, election vote,
selector, resource allowance or deadline is introduced.

Focused tests use real typed preparation, actual pending owners, TCP transfer
and filesystem force, with conditional old-voter histories. They cover both
published phases, three interrupted-force boundaries, changed parent bytes,
closed/incomplete acquisition, and the original standalone INTENT route.
The [component receipt](phase3-evidence/pending-published-retention.json) records
actual execution and preserved failures. Pair cold recovery, process death,
native installation, all profiles and independent physical/history replay remain
separate requirements.

The subsequent [pair recovery component](PHASE_3_PENDING_PAIR_RECOVERY.md) adds
original-first close/reopen. The voter capability remains gated on complete
linked custody and placement.
