## Exact original capture

The native owner can now grant a higher ballot while its actual certified
application has an unresolved future intention. Before writing PROMISE, it reads
and checks its active local GSPR and GSFT; capture includes the original GSFT
bytes in the source inventory. The GSRP wrapper binds the new original PROMISE,
the current ordinary ledger and the SHA-256 of that separately indexed GSFT.
BASIS binds the complete inventory and its capsule. The future application's
original ballot and certificate remain unchanged; the new grant does not create
new ACCEPT, PROOF or application acknowledgements for that old work.

An empty initialized GSFT has no obligation and uses the existing flags-zero
wrapper, byte for byte. A pending GSFT uses flags one and appends its 32-byte
SHA-256 after the existing two length-prefixed fields. No other flags are valid.
The wrapper's existing 73,784-byte ceiling is unchanged: the reference consumes
space within it. A referenced GSFT is at most 3 MiB and remains a separate object
under the existing 8 MiB object and 32 MiB complete-packet limits. This avoids
nesting six complete catalogs in selector-coupled ledger metadata. Wire kinds,
public formats, image counts and frozen fixture bytes do not change.

The reader requires the exact matching original PROMISE, a single original
wrapper, the indexed future object, its native owner/root, its original parent
and its exact accepted ENTRY/ACCEPT. It returns defensive byte copies. These
checks identify an owned source's conservative obligation; they do not establish
new remote progress, authenticated missing ancestry or a new voting observation.

## Recovery and temporary selection boundary

Capture recovery can precede construction of the full journal users. It reads
only bounded active GSFT/GSPR bytes under the actual native lock, derives the
same original capture, and verifies the existing capture intent. Normal owner
opening then validates the real backing vote/application and re-forces the
original future record before any recovered grant is exposed. Candidates do not
substitute for active bytes. Duplicate PREPARE preserves the original snapshot.

Until selected installation has a durable owner for these separate proofs, all
native decision paths reject a matching future reference **before SELECTED**.
This includes a local voter with no retention ledger; it cannot silently ignore
a remote voter's obligation. The selected-ledger parser independently refuses
such a reference. This guard is an explicit unfinished integration boundary, not
the final automatic protocol. The earlier pre-PROMISE refusal is removed.

The current target may remain unpublished during these captures. No obsolete
applied end is retired, no retention endpoint is narrowed, and no source capture
is reported as a publication or dispatch permit.

## Validation scope

The qualification uses a real three-voter EMPTY bootstrap and first certified
BARRIER with actual applied ends. Native checks cover higher-ballot capture,
original proof identity, duplicate/reopen immutability, holder and other-voter
selection refusal, and missing/duplicate/foreign/damaged proof rejection.
Conditional malformed-source fixtures explicitly synthesize BASIS ownership only
to exercise negative parsing; they are not actual voting evidence.

The process matrix interrupts seven original capture boundaries by halt and
SIGKILL. Each case is reopened by another fresh JVM using only its native files.
Independent Python replay derives bootstrap, original campaign/votes, application,
future intention, new source inventory, exact interrupted/recovered file maps and
force/response ordering before evidence mutation checks. This is process-death,
not power-loss or all-seven-profile qualification. Existing no-future capture,
selected merging and publication checks remain separate regressions.

The [source-bound receipt](phase3-evidence/future-source.json) records 18 Java tests,
14 new process cases (28 fresh JVMs and seven lock probes), ten evidence negatives,
and matching normal/optimized/relocated replay. Nineteen focused Python regressions
and the legacy source matrix (14 cases and nine negatives) pass separately.
Before Phase 3 closes, selected installation must preserve every selected original
future obligation through source retirement, carry the exact entry into the new
ballot, and safely reconcile it with the actual resulting application. Future
source/completion headroom must be admitted before exposed dispatch intentions;
continuous offline recovery must then pass without enlarging the frozen bounds.
