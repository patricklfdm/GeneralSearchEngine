## Physical replay and retained failure

The [evidence index](phase2-evidence/covered-staging-process.json) binds the original
source/build, worker inputs, all transcripts/exit codes, physical snapshots, lock
probe results, successful replay and failed first attempt. Independent replay
first validates admitted original history, then derives every retained authority,
interruption state and force/delete ordering. It checks replay force ordering,
complete installation and exact process termination/lock results. Nineteen altered
evidence cases must fail for their specified reasons. Original evidence is
validated before mutations; normal, optimized and relocated replay must agree.

The first attempt completed its halt cases but its first lock probe found an
unlocked inode. The new test worker's directory-hash collection had opened and
closed `replica.lock` while holding its POSIX process lock. An isolated local
reproduction confirmed that closing this additional descriptor released the
kernel lock. This was test instrumentation, not an ownership-policy change in the
runtime. The corrected worker excludes the live lock from in-process hashing;
raw post-exit snapshots still retain it, and independent live probes verify that
the worker retains the kernel lock. The failed transcript remains failed.

This is a local Linux filesystem/process result, not power-loss emulation, a
network failover guarantee or maximum-capacity qualification. The typed producer
checks application semantics; the Python replay does not execute the core codec.
