# Published history acquisition under the original pending owner

Phase 3 remains **OPEN**. The private retained-source capability can now open one
bounded progress download under its actual typed head and existing resource pool.
Ordinary progress/enrollment still refuses pending state. A decoded plan, ACK or
source value cannot obtain this entry point.

## Exact value, independently proved publication

The existing discovery, prefix and complete-generation transfer paths perform
real correlated exchanges, finite same-request retries and full source/ancestry
verification. The result must extend both the typed prepared source and the
retained SEALED source, contain the same complete operation and typed receipt,
and be JOINT or COMPLETED for that target view.

The complete published history must include the exact original INTENT ENTRY and
CHECKPOINT, with its membership edge certifying that entry. The checkpoint binds
the unchanged application and projected catalog hashes; an intermediate catalog
need not be duplicated as a standalone object in a compacted COMPLETED history.
The independently verified certificate may use a later valid ballot for the same
entry. It must not substitute another entry/checkpoint merely because the typed
receipt or request matches. The original pending certificate remains retained.

The same guard checks the parent and original marker during the exchange and
before returning. Expiration, modified originals or parent close stop acquisition
and release scratch/network reservations. Scratch must be disjoint from both
the pending original directory and its former receiving path before contact.
It still uses one SOURCE for pending
history, one existing typed GENERATION and at most one LEARNER receiving slot.
No budget extension, extra receiving slot or public format is introduced.

## Deliberately separate durable transition

This entry is read-only acquisition. It cannot resample pending metadata, create
another pending owner, cancel, or call the ordinary full-INTENT retention path.
The latter still rejects coexistence with the pending sidecar. A separate linked
transaction must preserve the original pending marker and all leases before
handing the complete source to existing custody/placement/native installation.
Closing the download keeps the original pending evidence and removes only its
own receiving scratch.

Focused tests use real typed preparation, files and TCP with conditional old
voting histories. They cover JOINT/COMPLETED reads, incomplete SEALED refusal,
parent revocation at an actual response, original deadline and marker changes,
and the distinction between another valid certificate and another INTENT value.
Results are in the [component receipt](phase3-evidence/pending-published-progress.json).
These fixtures do not claim native elections, joined installation, independent
physical/history replay, process death or complete Phase 3 acceptance.
