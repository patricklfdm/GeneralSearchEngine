# Covered minority physical and process recovery

Phase 2 remains **OPEN**. This qualification extends the
[bare covered-minority implementation](PHASE_2_COVERED_MINORITY.md), with no further
production Java, format, resource limit, POM or workflow change.

The independent Python reader starts with the original public bootstrap plan,
projected application and all admitted voter files. It derives the minority's
original ACCEPT at ballot 2, the disjoint majority's real ballot-3 ACCEPT/PROOF/
certificate/application/checkpoint publication, and the all-voter ballot-4 sources
and selected generation. It authenticates the original minority parent through
the published range, then derives the exact installed selector, empty pending vote
and retained old source/generation. It also derives later governing-floor cleanup,
source retirement and the ballot-5 BARRIER. Every voter snapshot is compared in
full, including voters that did not participate in the majority publication.
Original observations are checked against the complete derived set, without
inventing witnesses. The chosen application image remains an original input whose
typed semantics are checked by Java; this is not independent semantic decoding.

The same reader derives twelve twice-interrupted local transactions. It models
candidate creation, partial bytes, file/parent force and rename separately; it
never treats a manifest or reported success alone as completion. The original vote
survives until the forced replacement, and its selected source and old generation
survive that replacement. The second recovery starts from the exact first state,
including any existing empty-container prefix. Original owner calls and force
order must agree with the derived transactions. Thirty evidence mutations reject
missing/damaged bootstrap, votes, proofs, sources, images, selected decisions,
call/observation omissions, premature clearing and wrong recovery traces.

A separate Java producer provisions an actual admitted three-voter EMPTY group.
For every one of the twelve boundaries it executes both `Runtime.halt(73)` and an
external process kill. It restores the same original admitted replica path before
each case; copying to an arbitrary path would not satisfy admission. The recovery
worker is halted again at the specified recovery boundary, then a third fresh JVM
completes installation. All workers use the actual original observations and
reopen the actual peer sources; no synthetic proof is substituted. The harness
checks real cross-process lock exclusion before each external kill, exit codes,
empty stderr, closed reservations and explicit completion.

This yields 24 cases, 72 recovery workers and 12 additional lock probes. The
process reader independently replays the original reference first, binds worker
paths to the immutable bootstrap descriptor, checks the exact observations,
derives all three snapshots per case and checks each complete stdout trace and
exit-code receipt. Nineteen process evidence mutations cover lost authority,
wrong force/death order, false returns, changed paths/observations, scope and
capacity flags. Both readers must first accept the unmodified originals, then
reject each mutation with its expected reason. Ordinary Python, `-O` and relocated
copy replay must produce identical results.

The [retained index](phase2-evidence/covered-minority-recovery.json) binds the
source inputs, original producer receipts, class/JAR inventory, raw file hashes,
JUnit records and both independent replay results. It retains the failed draft
reader attempts separately; they are not qualification successes. The preceding
runtime fix's 41 passing Java tests remain evidence for that exact runtime, whose
706 production class bytes are unchanged by this batch.

This does not qualify power loss, kernel/filesystem failure, maximum byte capacity,
backup/four-/five-voter profiles, configuration transitions, protected-context or
proof-bearing covered votes. It does not enable public online membership or
transport. Those remaining storage obligations stay on the
[Phase 2 closure checklist](PHASE_2_CLOSURE_CHECKLIST.md).

The later [six-profile extension](PHASE_2_RETIREMENT_SOURCE_IMAGES.md) adds clean
four-/five-voter and backup progress plus a distinct source-image retirement fix.
Its new transaction is not covered by this earlier process receipt.
