# Original joined predecessor retirement

Phase 3 remains **OPEN**. This component performs actual predecessor deletion
under the installed learner's exclusive custody, after
[independent original-history verification](PHASE_3_JOINED_ORIGINAL.md). It also
reopens an interrupted original retirement under real filesystem locks. It does
not open a mutable journal, publish an application, issue votes, or admit the
joining identity to public service.

## Authority and surviving files

Derive the deletion sequence from the original custody inventory projected
through the seven completed placement moves. No caller supplies paths or a
replacement inventory. Keep every original top-level root, every empty `.lock`
file and its parent directories, the complete installed native generation and
root metadata, and the selected original typed `preparation.json` / `learner.gsr`.
Keep the custody, placement and joined records unchanged. Preserve absent roots
as absent. Delete the remaining original learner, receiving, typed backup,
INTENT and obsolete staging payloads, including empty nested directories, in
root/name order with children before parents.

Before the first deletion, force a canonical original `retirement.json` and its
directory and parent. The separate private retirement directory binds the
reviewed plan, root/local identity, original directory and decision inode,
original joined proof fingerprint, derived deletion sequence and complete
reservation ledger. Its path must be disjoint from original roots and the
application materialization directory. The decision is bounded to 256 KiB;
`retired.json` is bounded to 64 KiB and binds its own inode and the complete
original decision. Neither record changes the public v1.3 byte catalog.

Every mutation boundary rechecks original proofs and the complete remaining
inventory, including directory identities, file inodes, lengths and hashes.
Only an absent prefix of the derived deletion sequence is accepted. A missing
survivor, a nonprefix missing predecessor, an unexpected member, or a substituted
original refuses. A deletion is followed by forcing its surviving parent.
Before completion, interrupted deletion prefixes are re-forced through their
nearest surviving original ancestors; all original root directories remain.

## Live and cold continuation

Live continuation uses the same actual custody and its original partially
written decision. A cold reopen requires a complete canonical original decision;
a missing or torn decision cannot be reconstructed from caller arguments.
Acquire the existing root lock and every surviving original empty lock without
creating files, restore the conservative reservation group, check the projected
inventory, and independently verify the installed source/INTENT/typed-proof
bindings before any force or deletion. Failure closes acquired owners and
reservations. Completion prefixes can continue only against the same original
plan and exact expected record bytes. A copied complete decision or completion
marker refuses its inode binding.

This is a private transaction owner. Read-only inspection diagnostics cannot be
converted into deletion authority. Ordinary placement recovery remains strict
and does not recreate predecessors deleted by this separate transaction.

## Conservative accounting

Staging reserves another 320 KiB for retirement before creating installation
bytes: total fixed private companions rise from 576 to 896 KiB within the same
existing GENERATION ceiling. No resource count, metadata, staging, image or time
limit increases. Live deletion retains the entire original reservation group.
The original ledger records categories and extents without transient process
owner names; cold recovery restores that group under the normal resource limits.
It verifies quiescent category/count shape and that declared metadata/image
extents cover the original physical inventory plus the private companions.
Already-deleted payloads do not lower that cold reservation requirement.

No lease is released merely because a file disappears. Exact reclassification
and transfer into the actual native journal/allocator are now implemented by
the separate [native handoff](PHASE_3_JOINED_NATIVE.md). That handoff adds 64 KiB
to upfront companions (960 KiB total); cold conservative accounting includes it.
Closing this transaction releases its owners and charges; retaining it does not
make a voter runnable. The installed immutable history must still receive typed
materialization and native runtime checks before service.

## Qualification boundary

The [component receipt](phase3-evidence/joined-retirement.json) records actual
snapshot results and retained development failures. Tests execute real deletion,
live partial-write continuation and exception/cold reopen across decision,
delete/parent-force and completion boundaries. They cover exact surviving files,
independent JVM root exclusion, conservative accounting, missing/torn/copied
records, altered deletion lists, nonprefix absence, undercharging, last-boundary
corruption, and a promoted completed replacement's selected typed proof.

These historical source fixtures retain conditional quorum observations. This
batch is not native full-history, all-profile or halt/SIGKILL qualification.
The separate native handoff now consumes the actual descriptors/reservations.
[Deferred acceptance](PHASE_3_DEFERRED_ACCEPTANCE.md) still requires minimum-quorum
INTENT, joined retention, joint FINAL/fresh-barrier integration and full
original-first physical/history replay before Phase 3 can close.
