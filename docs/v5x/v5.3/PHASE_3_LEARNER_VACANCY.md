# Phase 3 — durable cleared learner slot

[A25](PHASE_3_CONTRACT_AMENDMENTS.md#a25--original-durable-vacancy-before-alternate-slot-reuse)
makes the completed removal boundary persistent. The selecting head still
identifies the exact old source and typed members. Once every member is gone and
both surviving parents are forced, an original vacancy record is forced and
selected before the old leases release. It binds its own inode, the selecting
head's bytes/inode, the slot plan and all three covered fingerprint inventories.

A complete retained candidate can resume using the same inode and bytes. A copied,
partial or foreign record is not repaired; recreated old roots refuse even when
their files are otherwise small. Cold recovery independently validates the current
B source and typed originals before any recovery forces. After re-forcing the
original vacancy, it no longer needs phantom reservations for the absent seed.
Without that record the same absence still requires conservative A24 accounting.

This is the durable boundary needed by the next inactive-slot plan. It does not
yet authorize another acquisition or installation. Old source/typed paths still
must remain absent, and Phase 3 remains **OPEN**. The final repeated-slot owner
must distinguish this exact cleared predecessor from the next candidate and keep
all current/pending resources under the existing two-generation/seven-image pool.

## Verification scope

The [component receipt](phase3-evidence/learner-vacancy.json) binds exact source,
compiled identities, commands, reports and any failures. Conditional histories
exercise actual files, core semantic decode and synchronous exception cuts; they
do not establish native consensus or process-death qualification.

The focused suite checks force-before-release, cold recovery with another occupied
generation slot, refusal of the same missing old files without the original
vacancy, complete-candidate and rename-cut recovery, incomplete candidate refusal,
copied marker identities and recreated old roots. The existing positive TCP
selection/retirement/cold-reopen history and resource-owner tests accompany it.
Long native/process-death and maximum-resource matrices remain in the
[deferred queue](PHASE_3_DEFERRED_ACCEPTANCE.md).


## Portable binding inspection

```bash
python3 -B -m scripts.v53.learner_vacancy_evidence RAW_DIRECTORY/reopened-slot-head
```

This component first checks the portable snapshot inventory and original identity
observations, then independently binds the vacancy to the selecting inode,
current plan/source/generation/receipt, immutable seed metadata and typed members.
Both original candidate and active locations remain distinct; neither a copied
inode nor a hash of the wrong predecessor can pass. It never opens recorded old
absolute paths. Nine binding tests and eleven copied-snapshot parser tests use
conditional records; they are not native execution evidence.

Result status is always **PARTIAL**, with force ordering, native history, reuse
authorization and full phase acceptance false. A complete original history reader
still has to establish source certification, the original head and actual force
trace before this component's checks can contribute to qualification.
