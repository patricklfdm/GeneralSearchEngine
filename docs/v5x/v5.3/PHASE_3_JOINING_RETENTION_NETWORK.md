# Joining retention acquisition from original old voters

Phase 3 remains **OPEN**. The joining owner can now request each old voter's
frozen retention fragment over the existing bounded transfer path, assemble an
exact old majority, and present a live acquisition handle to the durable
three-ledger initializer. The coordinator must still arrange the old voters'
fresh grants. This component does not schedule that campaign, connect public
service, or establish complete native/process qualification.

The private lookup digest binds the root, exact joining identity and current
JOINT cut. The exporter reads the actual owner's original BASIS, source envelope
and peer/learner retention wrappers. It checks the active grant and unchanged
current cut, and refuses an accepted tail or unsettled future in the frozen
source. Existing CHUNK, SOURCE_OFFER and TRANSFER_COMMIT records carry the bytes;
there is no new wire kind or persisted seed format. A prefix borrow binds the
original generation and deadline. A higher observed ballot or replaced owner
revokes access. The last exact commit closes the export while the bounded
completion marker preserves an identical lost-reply retry.

The receiver visits distinct old identities in canonical order. Transport IO or
deadline exhaustion may move to another old voter, within the same original
acquisition deadline; explicit rejection, corruption, capacity failure and
closed ownership stop the acquisition. Existing frame retries remain bounded
and identical. Every received BASIS must name the requested peer, current root,
JOINT view and exact installed cut. All selected fragments must use one ballot.
The existing seed reader rechecks included inventories, catalog/application,
ancestry, old-majority membership and conservative ledger unions. It preserves
peer uncertainty and learner renewal debt rather than synthesizing empty ledgers.

Only the actual unused native joining owner can create the acquisition. Its
current generation, original installation, observed fence and resource pool
remain bound through initialization. Decoded fragments or a returned seed value
are data, not installation authority. The journal obtains an admitted use from
the live acquisition before invoking the unchanged seed/three-ledger/completion
transaction. Close immediately revokes new uses and cancels a pending pull.
An initialization already admitted under the journal monitor retains its control
charges until that transaction exits. Interrupted initialization keeps the
existing explicit original-decision recovery path; the network entry cannot
reconstruct missing originals or repair a completed initialization.

Each fragment is capped at 2 MiB: the existing 1 MiB envelope, bounded BASIS and
two bounded retention wrappers fit after Base64 encoding. Export materialization
and each retained received fragment reserve 6 MiB of CONTROL. A three-of-five
old majority therefore reserves at most 18 MiB for fragments. Final assembly
reserves three additional extents, each bounded by the actual combined fragment
bytes plus 16 KiB and the existing 8 MiB per-extent cap. Transfer buffers and
reply caches continue using their own existing reservations. The shared 64 MiB
queue can still reject concurrent work; this arithmetic is not qualification of
every maximum combined workload. No staging, image, source, journal or time
allowance is enlarged.

Focused tests use actual on-disk source exports and framed exchanges over
conditional certified fixtures. They check exact original fragment/seed bytes,
lost offer/data/commit replies, export release, higher-ballot revocation,
oversized or altered offers, original deadline expiry, pending-pull cancellation,
and rejection of a conditional owner as an initialization capability. Existing
seed tests cover all add/replace profiles, conflicting majorities and retained
uncertainty; existing transaction and transfer tests remain separate checks.
These results do not establish a native joining history.
