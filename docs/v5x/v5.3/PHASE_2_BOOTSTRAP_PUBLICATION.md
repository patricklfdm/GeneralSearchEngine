# Admitted initial voters through actual publication

Phase 2 remains **OPEN**. This joins [public offline bootstrap](PHASE_2_PUBLIC_BOOTSTRAP.md)
and [admitted storage](PHASE_2_BOOTSTRAP_STORE_ADMISSION.md) to real phased votes,
typed application, publication and reclamation. No conditional historical ownership
observations are supplied to this chain.

Six independent groups cover EMPTY and verified durable backup inputs at initial
sizes 3, 4 and 5. Each uses public `planBootstrap` / `applyBootstrap`, its retained
random history and immutable preparation/admission/seal records. Every subsequent
owner opens through `openBootstrapped`, with the exact materialization binding.
The offline public entry does not enable online membership service.

Each group executes the following continuous local sequence:

1. The real proposer allocates ballot 2. All initial voters force original sources,
   SELECTED and its exact installation, establish a governing floor and retire the
   inactive generation before voting.
2. All voters accept/prove/certify a BARRIER at slot 1. Actual core replay and real
   checkpoint acknowledgements produce a common published cut.
3. The same original selection accepts/proves/certifies one DATA ADD at slot 2.
   Repeated exact ACCEPT/application/publication calls return the original result;
   the typed final image contains `Doc(303, "admitted-original")` exactly once.
4. The proposer allocates ballot 3, captures the actual slot-2 publication, installs
   a fresh selection, and reclaims the old source. Slot 3 publishes another BARRIER.

The 24 admitted voters perform 72 node publications. The producer checks the actual
application history/sequence, immutable bootstrap bytes after every snapshot, exact
duplicate results, two settled image reservations per owner and no lease leaks.
It reads the original public bootstrap result after each publication; mutable
progress must not rewrite or invalidate that original result. EMPTY finishes at
application sequence 1; backup import starts at 41 and finishes at 42.

The [local evidence index](phase2-evidence/bootstrap-publication.json) retains both
producer attempts, exact compiled inputs, JARs, producer/runtime classes and raw
snapshots. The first attempt supplied an unused intermediate ancestry bridge at
the second installation; the implementation correctly rejected it. The corrected
producer supplies no unnecessary bridge: its obsolete source is the genesis
anchor already authenticated by the selected capsule. Runtime checks are unchanged.

Independent Python replay derives all original admitted files from the retained
plan/image, then derives grant/source inventories, selected sets, installations,
ACCEPT/PROOF/certificate bytes, applied-end metadata and acknowledgements, complete
published generations and exact reclamation. It checks all 624 subsequent node
snapshots, exact DATA payload encoding, six distinct histories, observed ownership
records, required force-before-response boundaries and typed inspection bytes.
Twenty-five original-first mutations, optimized Python and relocated replay must
agree. The small Python tests cover malformed originals, images and inventories.

The producer's core reader verifies application semantics. Python verifies exact
image bytes and catalog projection; it is not an independent typed application
implementation. The original projected image and declared source-backup inventory
are retained here; the original backup's three input files are not duplicated in
this batch. Source verification also remains covered by the existing typed
bootstrap/revalidation gates. Reservation peaks are callback observations, not
independent reconstruction of maximum physical capacity: seven image slots were
observed, with small images and metadata.

This adds clean stable-view lifetime evidence on the current production artifact.
It does not establish complete cross-view old/joint/new operation, interrupted
admitted publication, minority ENTRY resolution, maximal journal/image/staging
headroom, network progress or power-loss behavior. Those remain separate entries
in the [closure checklist](PHASE_2_CLOSURE_CHECKLIST.md). No production Java, POM,
workflow, format or frozen bound is changed by this qualification.
