# Phase 3 — fresh-process service fencing after native departure

Status: locally qualified. This extends the actual
[native departing FINAL](PHASE_3_DEPARTING_PUBLICATION.md) histories. It does not
close Phase 3, enable a public runtime or qualify interruption during FINAL
installation.

## Actual history and process boundary

Both original four-to-three REMOVE profiles run through the native network:
the departing node is either the original proposer or a selected follower.
Every original owner and transport closes before fresh workers reopen that same
node's original absolute directories. The test does not relocate admission or
replace the live store with a copied fixture.

For each history, two workers halt and two workers receive SIGKILL at
`PUBLICATION_ACK_BEFORE_RETURN`, before the caller receives a completed ACK.
Each live SIGKILL worker must reject a separate storage-lock open with the exact
cross-process ownership error. After every interruption the complete store must
remain byte-identical to its original completed FINAL.

A final worker returns the exact retained publication ACK twice, rejects a
higher-ballot new-view PREPARE, then returns the same original ACK again. It also
rejects activation, readiness and new slots. No new allocator, promise, governing
floor or publication selector authority may be forced, and no new remote observation may
be acquired. Re-forcing unchanged originals during native reopen is expected and
remains recorded. All resources must be released after normal close.

The selected follower reuses its actual original TCP request. The proposer
completed locally; its repeat request is reconstructed from the exact original
local reply, explicitly labelled in the evidence. The reopened workers call
the actual endpoint directly with their transport open. This is not restarted
TCP-delivery qualification.

## Independent qualification

The reader first validates the entire original native history. It then compares
every interrupted/reopened store, binds requests and replies to the original
publication, derives the rejected PREPARE from the actual new view and permanent
identity, and checks distinct child processes and exact interruption boundaries.
A success marker cannot replace those checks. Fourteen reason-specific mutations
per profile target authority bytes, ACKs, request binding, process identity,
interrupted-store changes, lock observations and false service readiness.

Two Java process profiles pass: eight interrupted children, two normal resumes
and four live cross-process lock refusals. Five reader tests pass. Both original
histories and their relocated `python -O` replay pass fourteen exact negative
variants each (twenty-eight across the two histories). The
[source-bound receipt](phase3-evidence/departing-restart.json) binds the immutable
1,138-file Java/resource/POM inventory, complete original evidence and frozen
readers in a verified portable archive. No production Java or format changes
are included in this batch.

The first actual process attempt failed before ACK interruption: the endpoint's
private scratch parent did not exist, and path admission rejected it. The worker
now creates its unique test-private parent before opening the endpoint. The
failed native history and child stderr remain retained; production path validation
is unchanged. This failure does not establish a protocol recovery defect.
